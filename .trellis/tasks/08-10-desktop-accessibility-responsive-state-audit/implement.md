# Desktop accessibility, responsive, and state audit - implementation plan

## Preconditions

- [ ] Confirm visual foundation and all five surface/shell tasks are green.
- [ ] Read the parent UX audit and current accessibility matrix.
- [ ] Inventory route nav, tabs, menus, dialogs, collapsibles, forms, repeated
      actions, async statuses, and scroll owners before changing code.
- [ ] Resolve recovery initial focus by reconciling implementation, test, and
      spec; record the chosen work-preservation/safest-action rationale.

## Implementation sequence

- [ ] Classify and repair navigation/tab semantics; add shared behavior only
      where at least two true tab widgets need the same complete model.
- [ ] Complete the Workbench menu keyboard contract and panel/PDF/TM focus
      handoff, including opener restoration and visible focus.
- [ ] Add surface-transition focus/announcement behavior that runs only on a
      route-kind change.
- [ ] Normalize labels, repeated action names, form errors, live statuses, and
      destructive confirmations across P0-P4.
- [ ] Measure all matrix states at 1180x700 first; implement content-responsive
      wrapping/tracks/scroll ownership, then recheck wider viewports.
- [ ] Verify theme contrast, reduced motion, text scale/zoom, forced colors, CJK
      composition, and stable hit areas; keep non-automatable lanes explicit.
- [ ] Extend Playwright helpers and focused component tests for every repaired
      semantic/focus/geometry contract.
- [ ] Update `docs/accessibility-matrix.md` only with evidence generated by this
      task; do not mark native/manual lanes passed without the named run.


Runtime matrix: 1180x700, 1250x744, 1680x942, 1920x1080; light/dark; 125%
text scaling; 200% zoom stress; reduced motion; long CJK/IDs; forced colors when
supported. Record console/page errors for every case.

## Review gates

- [ ] Semantics match keyboard behavior; no ARIA role is decorative metadata.
- [ ] Focus never falls to body after a close, collapse, Escape, or surface move.
- [ ] All dynamic failures and progress are announced without focus theft.
- [ ] Axe output is complete or every baseline entry has an owner and reason.
- [ ] No capability is hidden solely to make the compact matrix pass.

## Rollback points

- Navigation widget semantics and tests.
- Focus/announcement helpers and callers.
- Form/status/destructive-action semantics.
- Responsive CSS and viewport harness.

If a cross-cutting change regresses domain behavior, revert that family and
return the defect to the child that owns the surface.
