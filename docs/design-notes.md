## 1. 平台与技术栈（已拍板）

- **平台**：Windows 10+ / macOS 12+ 双平台；**不做 Linux 端**。
- **UI 壳**：**Electron + TypeScript**。弃 Tauri，理由：三平台三种 webview（WebView2/WKWebView/webkit2gtk）的 CJK IME 行为不一致且存在现行 bug（如 tauri#15436 WebView2 IME/TSF 首聚焦冻结）；本产品编辑器的 CJK 输入体验是 P0（PRD C-13），Chromium 是 CJK IME 测试最充分的渲染器，选 Electron 等于买断该风险。
- **引擎核**：**Rust 无头进程（Headless Engine Core）**。过滤器/管线、TM/术语检索、QA、资产中枢、存储的全部逻辑与数据都在引擎核；性能 NFR（百万句对模糊查询 P95≤200ms 等）由 Rust 层兑现。
- **前端纪律**：前端只做展示与交互，**零业务逻辑**。TM 匹配、分段、QA 规则等绝不在 TypeScript 实现——否则 CLI/团队容器无法复用。前端一切能力经引擎核接口获得。

## 2. 架构分层（已拍板）

```
┌───────────────────────────────────────────┐
│ 前端 UI（Electron 渲染进程 / TypeScript）      │  只管展示与交互
│ 编辑器网格 · 面板 · 预览 · 设置                │
└──────────────────┬────────────────────────┘
                   │ IPC（本地进程通信，非网络）
┌──────────────────┴────────────────────────┐
│ 引擎核（Rust 无头进程）＝ 真相源              │  全部逻辑与数据
│ 过滤器/管线 · TM/TB 检索 · QA · 资产中枢 · 存储 │
└──────────────────┬────────────────────────┘
                   │ 同一套协议（关键设计）
        ┌──────────┼──────────┬─────────────┐
       CLI      本地 API    团队容器（M2，同一引擎多用户模式）
```

- **承重决策**：引擎核拥有存储，**GUI 永不直连数据库**。由此，X 模块（CLI/API/watch）、I-05 团队容器、插件协议都成为"同一引擎的不同部署/接入形态"，而非重构。
- 本产品的"前后端分离"分离在**引擎核边界**，而非网络边界：默认同机 IPC（本地优先）；仅团队模式下引擎核进容器、走网络。

## 3. 插件系统：三层模型（基线已拍板，细节待 design.md）

| 层 | 形态 | 覆盖 | 隔离/权限 |
| --- | --- | --- | --- |
| Tier 1 | **声明式清单**（manifest/YAML，零代码） | 简单格式过滤器（抽取规则声明）、OpenAI 兼容引擎连接器（endpoint 模板+认证+映射）、QA 正则包、AI 动作提示词 | 天然受控（无代码），权限可完全强制 |
| Tier 2 | **沙箱 JS**（isolate/iframe + postMessage API 面） | 编辑器 UI 面板、带逻辑的 AI 动作 | API 面强制权限 |
| Tier 3 | **进程外协议插件**（子进程 + stdio JSON-RPC；任意语言含 Python/Java） | 复杂过滤器、复杂连接器、管线步骤（如 Okapi 桥接插件跑 JVM 服务长尾格式） | 崩溃隔离免费；权限=声明+用户授权+信任（OS 层无法真禁足，诚实写明） |

- **协议先行**：按扩展点定义协议（Filter/Engine/Step/QA Protocol）；大文件传路径不传字节、事件流式（Okapi 事件模型映射）。
- **官方吃狗粮**：内置格式/引擎用同一套协议实现（进程内直连转发）。
- **WASM**：不作 M1 承诺；将来需要"真沙箱高性能过滤器"时给 Filter Protocol 加 WASM 传输层即可。
- **Okapi 处理**：取其设计（filter/step/pipeline 范式）+ 经 Tier 3 桥接插件复用其现成过滤器；核心高频格式（docx/xlsx/pptx/pdf）Rust 原生实现。

## 4. 存储与资产中枢（基线已拍板）

- **真相源**：SQLite 单库（WAL，段级持久化）；项目、TM/TB、来源元数据、质量分、养护日志皆在此。
- **派生索引皆可弃**：模糊检索/Concordance 用 tantivy 类倒排（CJK 用字符 bigram/分词混合召回 + 编辑距离精排）；向量索引（usearch/lance 文件）只对养护批次/高价值子集按需嵌入 + 量化，不全量。索引损坏/升级即重建；备份=拷数据目录。
- **段落身份**：内容寻址（源文+上下文哈希）+ 来源/时间/项目 provenance 元数据（PRD AC-02）。这是去重、同步合并、养护回滚的公共地基，**现在定死，事后难改**。
- **团队共享拆两件事**：
  - **资产（TM/TB）= 本地副本 + 后台同步**：读永远本地（敲字查询零网络延迟），写走段级 op-log 同步到容器，LWW+墓碑合并（TM 追加为主，天生好合并，不需重型 CRDT；可参考/采用 libSQL 嵌入式副本模式）；
  - **实时协作会话（段锁/在线状态/看板）= 在线服务**：本来只在在线时有意义。
- 网盘/Syncthing 同步 SQLite：**只支持只读参考库分发**，文档明说，不承诺多写。
- 扩容触发条件是**多写者**而非数据量；2–10 人团队容器内 SQLite 足够，Postgres 为远期可选。

## 5. 开发方式（已拍板）

- **个人开发、长期项目、串行推进，不并行。**
- 顺序：**① 前端原型（本阶段）→ ② 引擎核骨架（过滤器/管线接口 + SQLite + docx 过滤器 + 一个引擎连接器）→ ③ 最小端到端链路（导入 docx → 翻一段 → 导出）→ ④ 沿 PRD 优先级迭代**。
- TM 检索基准测试（tantivy CJK 1M/10M）**延至引擎核开发期**执行。

## 6. 前端设计立场（本阶段核心）

- **拒绝极简安全牌**。原型阶段大胆探索、艺术风优先；宁可先过火再收敛，不要一开始就平庸。
- **纪律边界**：艺术性活在 chrome（框架、面板、空态、向导、仪表盘、图表）；**编辑器网格本体保持功能纪律**（行高、对比度、扫读效率不为风格让步）——每天盯 8 小时的区域，美学为可用性服务。
- **方向改版（2026-07-16 第二轮）**：第一轮三候选（植物志/凸版印坊/水墨文房）**整体废弃**。
  新方向 **Translunar（转移轨道）**：以《明日方舟·孤星》全套设计为结构蓝本，融合三种复古未来主义——
  NASA 朋克（工程务实、国际橙、模板喷字）、磁带盒未来主义（仪表台质感、指示灯、等宽遥测读数）、
  原子朋克（轨道环/星爆等乐观图形母题）。调研纪要见 `docs/design-research-retrofuturism.md`。
- **概念隐喻的边界（2026-07-17 收敛）**："翻译项目=一次航天任务"只用于内部构思和视觉母题，
  **不替换产品术语与操作文案**。界面继续使用项目、文档、翻译记忆、术语库、QA、AI 建议、确认、导出等
  真实 CAT 词汇；载荷、飞行记录、制导、GO/NO-GO、发射倒计时等不得成为导航、按钮、状态或功能名称。
  航天感由版式、仪表刻度、轨道线、方形状态灯和色彩承担，用户不需要先理解世界观才能工作。
- **核心配色**（孤星实测谱系）：任务纸白 #F5EFE2 + 软黑 #221B18（拒绝纯黑）+ 信号橙 #F25C1A（唯一强调色）；
  状态灯：确认绿 / 警告赭黄 / 错误红；字体：Space Grotesk（克制的展示文字）+ Chivo（正文与控件）+
  Space Mono（段号、百分比、计数、时间戳与快捷键）。不再设置仅为装饰服务的面板微标签字体。
- **标志性图形（2026-07-17 新增）**：加入固定顺序的五色复古彩条 Translunar Band（橙/赭黄/苔绿/仪表青/暮蓝），
  作为每屏最多一次的品牌签名；功能交互仍以信号橙为主强调色，彩条各色不承担按钮、状态或图表语义，且不进入编辑器网格。
- **v0.1 / v0.2 评审收敛（2026-07-17）**：以 v0.2 的真实 CAT 信息架构、可读性和操作闭环为产品骨架，
  恢复 v0.1 中更深的暖纸底、非对称构图、工程制图线条、面板层次与底部文件预览。目标约为 75% 产品结构 +
  25% 艺术层；非功能装饰本身允许存在，但不得伪装成控件、数据、坐标或系统消息。
- **《孤星》专项纠偏（2026-07-17）**：核心识别来自现代主义网格、几何抽象、大面积非彩色底、暖黑/橙、
  原色彩条与太空时代几何字体；毛玻璃、警戒条、工业颗粒属于方舟本体也常用的机制，只作辅助。
  五色 Translunar Band 是对《孤星》原色上升彩条的 CAT 品牌扩展，不宣称为活动原样复刻。
- **文件预览（P0）**：主工作台恢复底部可折叠、可拖拽的联动 Document Preview；收起约 32px，默认展开约
  200px，可调 120–320px，仅位于网格下方并与当前句段双向定位。
- **动效立场**：不再以“尽量少动”为目标，而采用分层动效。高频编辑反馈 70–160ms，面板/预览 180–240ms，
  工作区转场 240–320ms，低频项目页可到 360–480ms；艺术动效集中在 chrome、页面层级和一次性线条/彩条揭示，
  网格文本不做逐字动画或永久循环。IME 组合态期间禁止确认、移焦和布局动画。
- **视觉锚点（2026-07-17）**：`docs/ChatGPT Image 2026年7月17日 20_04_16.png` 基本达到目标，后续页面以其
  产品/艺术平衡、暖黑顶栏、五色彩条、网格密度、Suggestions 切角标题、展开式文件预览和暖黑底栏为母版。
  图中悬浮在网格与 Suggestions 之间的双箭头胶囊是明确缺陷，不得继承。
- **圆点矩阵**：升级为正式装饰纹理，用于面板标题空余区、外侧 gutter、预览边缘、底栏端部和空状态；
  必须为规则正交矩阵、低对比、裁切成块、与结构网格对齐，不进入任何正文或输入区域，也不持续动画。
- **Suggestions 折叠**：展开状态只在标题右端显示一个向右 chevron；收起后只保留贴附窗口右缘的窄轨道和一个
  向左 chevron。不得同时显示双向箭头，不得使用悬浮胶囊遮挡网格或匹配内容。
- **布局纪律沿用**（UX 决策与美术无关）：两区工作台、无常驻左栏、顶栏文档切换 chip、网格上方高频筛选工具条、空间按使用频率分配。
- 最终方向待：Stitch 原型（Translunar）+ 生图灵感对比（A 任务控制台 / B 磁带盒 / C 原子朋克三种配比）→ 评审后定稿，再产出正式设计系统。
