## 1. 键盘全图

### 1.1 上下文优先级（冲突解析）

```
IME 组合态  >  模态 Dialog  >  Popover/菜单  >  抽屉  >  可编辑单元格  >  网格  >  全局
```

高优先级上下文**吞掉**它声明的键；未声明的键向下传递。
`Esc` 是唯一逐层冒泡的键：每次按下只关闭最上层。

## 2. 焦点模型

### 2.1 网格内的 roving tabindex

网格是一个 `role="grid"`。整个网格在 Tab 序列里**只占一个停靠点**；
进入后用方向键在行/单元格间移动（`aria-activedescendant` 模式）。
理由：1,248 行 × 5 列 = 6,240 个 Tab 停靠点是不可接受的。

| 键 | 行为 |
| --- | --- |
| `Tab` 进入网格 | 焦点落在**活动行的译文单元格**（不是第一行） |
| `↑ / ↓`（非编辑态） | 上/下行 |
| `← / →`（非编辑态） | 左/右单元格 |
| `Enter` | 进入编辑态（译文单元格） |
| `Esc`（编辑态） | 退出编辑态回到单元格导航，**保留已输入内容** |
| `Tab`（编辑态） | 移到下一个可编辑单元格（不跳出网格） |
| `Ctrl+Tab` | 跳出网格到下一个区域 |

### 2.2 焦点归还

| 触发 | 关闭后焦点回到 |
| --- | --- |
| 命令面板 | 打开前的元素 |
| 任意 Popover / 菜单 | 触发按钮 |
| Dialog | 触发元素；若触发元素已卸载 → 其容器 |
| Drawer | 触发元素 |
| Toast 中的撤销 | 撤销后回到执行动作时的位置 |
| Document Matrix 跳转 | **保留在译文单元格**（跳转不夺焦点） |

## 3. IME 契约（P0 · CJK 一等公民）

> PRD C-13 与 design-notes §1 把 CJK IME 体验定为选择 Electron 的**唯一理由**。
> 这一节是不可协商的。

### 3.1 组合态期间**禁止**的行为

在 `compositionstart` 与 `compositionend` 之间：

- ❌ 触发任何全局快捷键（含 `Ctrl+Enter` 确认、`Ctrl+K` 命令面板、`Esc`）
- ❌ 移动焦点（含自动前进、QA 跳转、Matrix 跳转、面板切换）
- ❌ 切换标签、展开/折叠面板、打开抽屉或弹层
- ❌ 对译文单元格做高度过渡动画（`field-sizing` 的增高必须瞬时）
- ❌ 弹出自动补全幽灵文本
- ❌ 执行拼写检查的重排（可延后到 `compositionend`）
- ❌ 触发 `input` 驱动的草稿写盘（延后到 `compositionend` + 400ms）

### 3.2 实现契约

```ts
// 全局单例：组合态守卫
let composing = false;
export const isComposing = () => composing;

document.addEventListener("compositionstart", () => {
  composing = true;
  document.documentElement.dataset.composing = "";
}, true);

document.addEventListener("compositionend", () => {
  composing = false;
  delete document.documentElement.dataset.composing;
}, true);

// 所有快捷键分发的第一行
export function onKeyDown(e: KeyboardEvent) {
  if (composing || e.isComposing || e.keyCode === 229) return;   // 三重保险
  …
}
```

```css
/* 组合态期间关闭单元格的一切动画 */
html[data-composing] .cell-target,
html[data-composing] .seg-row { transition: none !important; animation: none !important; }
```

> `e.isComposing` 在某些 Windows IME 的 `keydown` 上不可靠，`keyCode === 229` 是必要的补充；
> 再叠加自己维护的 `composing` 标志，三重保险。

### 3.3 候选窗空间

译文单元格必须留出候选窗的呼吸空间：

- `scroll-margin-block: 96px`——滚动到该单元格时上下各留 96px，候选窗不被视口边缘裁切。
- 单元格下方 8px 内**不放**任何可点击控件（内联 QA 条至少距 8px）。
- 单元格聚焦时若距视口底部 < 140px，自动滚动使其上移。

### 3.4 CJK 排版辅助（引擎侧，界面只做开关与呈现）

| 功能 | 界面 |
| --- | --- |
| 中英之间空格建议 | 在译文单元格下方以 §A8 内联条提示 `建议在 "API" 前后加空格` + `应用` / `忽略`。**不自动改** |
| 全半角标点纠正 | 同上，可在偏好中设为自动 |
| 简繁转换 | 见 `screens/workbench.md §8` |
| CJK 字符计数 | 仪表条与分析页分别显示 `词` 与 `CJK 字符`，不混为一谈 |

**永不用 CSS `letter-spacing` 伪造中英间距**——那会破坏选择、复制与查找。

## 4. 指针交互

### 4.1 拖拽调整（Resize）

| 目标 | 手柄 | 范围 |
| --- | --- | --- |
| Stack 宽度 | 网格/Stack 之间的结构缝，命中区 8px（视觉仍 1px） | 360–560 |
| 预览坞高度 | 坞把手上缘，命中区 8px | 120–360 |
| 原文/译文列宽 | 两列之间的缝 | 30%–70% |
| 匹配/术语区高度 | 两区之间的缝 | 术语区 80–40% |

规则：拖拽期间 `transition: none`（跟手）；`cursor: col-resize / row-resize`；
双击手柄复位默认值；**键盘可达**（手柄 `tabindex=0`，`←→`/`↑↓` 每次 8px，`Shift` 加速 ×4）；
拖拽中显示当前尺寸的 Mono 数值（锚定在手柄旁）。

### 4.2 拖放（Drop）

| 落点 | 行为 |
| --- | --- |
| 项目首页 | 建新项目（预填文件） |
| 洞察 → 文件 | 加入当前项目 |
| 向导第 3 步 | 加入待导入列表 |
| 资产 → 语料 | 导入为参考语料（先问种类与语向） |
| 工作台网格 | **不接受拖放**——避免误操作污染正在编辑的文档。显示"拖放到项目文件页以添加文件" |

拖入时：目标区域 `--shade` 底 + 1px `--signal` 虚线边 + 内部 Inert Matrix 淡入 + 顶部说明条。
拖离/失败要有明确回执，不静默。

### 4.3 悬停

- 悬停不承载必需信息（§F1）。
- 悬停延迟：tooltip 400ms；行内动作条 120ms；Matrix 点 tooltip 120ms。
- 悬停消失：80ms。移动到 tooltip 上时不消失（安全三角）。

### 4.4 右键上下文菜单

| 区域 | 菜单 |
| --- | --- |
| 段落行 | 确认 / 复制原文 / 清空 / 锁定 / 拆分 / 合并 / 添加术语 / Concordance / 批注 / 复制段号 |
| 原文选区 | 划词 AI 动作 / 添加术语 / Concordance / 复制 |
| Document Matrix | 只看未翻译 / 只看有问题 / 跳到第一个问题 / 复制段号 |
| 匹配卡 | 插入 / 复制译文 / 在 TM 中查看 / 举报错误匹配 |
| 文件列表行 | 打开 / 运行 QA / 预翻译 / 重导入 / 移入回收站 |

菜单用 §B5 Menu（Popover 锚定到光标位置）。**始终提供等效的键盘路径。**

## 5. 选择模型

| 层 | 选择单位 | 视觉 |
| --- | --- | --- |
| 文本选择 | 字符 | 系统选择色（`::selection` 用 `--signal-wash`，文字保持 `--text-1`） |
| 段落选择 | 行 | 锚点行 = Active Axis；其余选中行 = `--shade` + 左缘 1px `--rule-strong` |
| 列表选择 | 行（表格/清单） | 同上 |

规则：
- 文本选择与段落选择**互斥**：在译文里选文本时不改变段落选择。
- `Shift+点击` 范围选择；`Ctrl+点击` 加减单项。
- 多选存在时，顶部滑入批量条（`screens/workbench.md §3.6`）。
- 切换筛选**保留**选择集（并提示 `已选 24 段，其中 8 段不在当前筛选中`）。

## 6. 撤销模型（两栈分离）

| 栈 | 范围 | 键 | 说明 |
| --- | --- | --- | --- |
| **文本栈** | 单个可编辑单元格内 | `Ctrl+Z` / `Ctrl+Y` | 浏览器原生 undo；离开单元格时该栈**不清空**，返回时可继续 |
| **文档栈** | 跨段操作（确认、清空、拆分、合并、批量替换、批量应用） | `Ctrl+Alt+Z` / `Ctrl+Alt+Y` | 应用级栈，无限深度（PRD C-17） |

**为什么分离**：单栈会导致"在单元格里按 Ctrl+Z 结果撤销了上一段的确认"。
两栈分离是密集编辑器的标准做法。

**不可撤销的操作**必须走 §F2 Confirm 并明说"此操作无法撤销"：
永久清除回收站、删除 TM 库、卸载插件、恢复快照（可用"再建一个快照"作为逃生）。

**批量操作**一律提供 §F3 Undo Toast（8s）+ 在操作历史中保留回滚入口。

## 7. 输入延迟预算

| 交互 | 目标 |
| --- | --- |
| 击键 → 字符出现 | < 16ms（一帧） |
| 点击 → 视觉反馈 | < 100ms |
| 切段 → 新段可编辑 | < 100ms |
| 切段 → TM/术语结果到达 | < 300ms（超过则显示 Skeleton） |
| 确认 → 状态方灯变化 | 立即（乐观），持久化失败再回滚 |
| 筛选 → 网格更新 | < 200ms（1 万段） |
| 命令面板输入 → 首屏结果 | < 120ms |
| Matrix 拖拽 → 网格滚动 | 同帧（无节流，用 `requestAnimationFrame` 合并） |
