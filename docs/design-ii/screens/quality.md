## 1. QA 复核（Surface `qa`）

### 1.1 推翻了什么

实拍 `21-qa-review.png`：QA 复核**根本没有独立页面**——它只是把工作台的 Stack 面板切到 QA 标签，
显示一列重复的 `qa.empty-target ERROR / Target is empty. / Source − Target −` 卡片。
问题：① 规则 ID 当标题（`qa.tag-tag_missing` 是给机器看的）；② 证据是两个空框；
③ 无法按规则/严重度聚合；④ 无法批量处理；⑤ 没有配置档编辑入口。

### 1.2 新版面：三栏（分布 / 清单 / 证据）

### 1.3 左栏：分布（Live Matrix + 筛选）

- **Live Matrix**：每点 = 一段，状态 = `无问题 / 警告 / 错误 / 已忽略`。
  点击某点 → 清单跳到该段的问题。这是"问题在哪扎堆"的唯一直观答案。
- 严重度计数（`错误 / 警告 / 提示 / 已忽略`），点击即筛选（chip 形式，Axis 在下缘）。
- 规则筛选（多选 Combobox，按规则名而非规则 ID）。
- 范围筛选：本文件 / 全项目（`qa.documentScope` / `qa.projectScope`）。
- 底部：`编辑 QA 配置档 →`（进入 §1.6）。

### 1.4 中栏：问题清单

每条问题一行（不是卡片）：

```
▎错误 · 标签完整性
  段 418 · 译文缺少受保护标签 1
```

| 元素 | 规格 |
| --- | --- |
| 左缘 3px | 严重度色（`--err` / `--warn` / `--machine`） |
| 第一行 | `严重度 · 规则显示名`（**人类可读名**，不是 `qa.tag-tag_missing`） |
| 第二行 | `段 n · 具体问题描述`（**必须含实际值**：`原文 30 / 译文 60`） |
| 插件来源 | 插件规则额外一行 §G5 Provenance Strip：`来自插件 <名称> v1.2` |
| 已忽略 | 整行降饱和 + `已忽略` 标记 + hover 显示忽略理由与操作人 |
| 选中 | `--shade` 底 + 左缘 Active Axis |
| 分组 | 按严重度分组，组标题 `--t-micro` + 计数，可折叠 |
| 键盘 | `↑↓` 移动、`Enter` 定位到段、`F8/Shift+F8` 上下条 |

**规则文案要求**（沿用并强化上一代的正确规定）：
`数字不一致：原文含 "30"，译文含 "60"。` —— 必须含实际值，不写 `Number mismatch`。

### 1.5 右栏：证据与动作

| 区 | 内容 |
| --- | --- |
| 段落定位 | `段 418` + 文档名 |
| 原文 / 译文 | `--deck` 底、`--t-editor` 字号。**触发问题的片段用 `--signal-wash` 底 + 1px 下划线标出**（上一代那两个空的 `Source −` / `Target −` 框是明确缺陷） |
| 规则信息 | 规则显示名、严重度、来源（内置/自定义/插件）、正则模式（若是正则规则，Mono 显示） |
| 动作 | `定位到段`（切到工作台并跳段）· `就地修复`（右栏内直接编辑译文并保存，不离页）· `忽略…`（§G8 Waiver，**必填理由**） |
| 相关段落 | 一致性类问题显示 `相关段落 n →`，展开列出同源异译/异源同译的全部段 |

**`就地修复`** 是新增能力：审校者在 QA 页连续处理 30 个问题时，不应该每个都跳回工作台。
右栏提供一个受限编辑器（可编辑译文 + 标签工具 + 保存并下一条 `Ctrl+Enter`）。

### 1.6 QA 配置档编辑器（抽屉，420px）

- 配置档选择 + `复制为自定义`（内置不可改，`qa.builtinImmutable`）。
- 规则表：规则名 / 严重度（下拉）/ 启用 / 参数（如 `目标最大字符数`）/ 删除。
- 自定义正则规则：名称 + 模式（Mono 输入，语法错误内联提示）+ 严重度 + 替换提示 + 作用字段。
- 强制审校开关（`qa.mandatoryReview`）与直接签发允许（`qa.directSignOff`）。
- 保存 → 提示"下次运行 QA 时生效"，并提供 `立即重新运行`。

### 1.7 审校者队列（Reviewer Queue）

`qa.reviewerQueue` / `qa.pendingProposals`：审校模式下的待处理提案。
以中栏的第二个分组呈现：`待处理提案 n`，每条含提案来源（AI / 插件 / 双语 DOCX 回导）、
before/after §D8 词级 diff、`接受` / `拒绝`。批量接受需二次确认。

### 1.8 运行历史

页头右侧 `最近运行 <时间> · <段数>` 可点击 → Popover 列出历史运行
（时间、范围、检查段数、错误/警告/提示计数、执行耗时）。
`qa.noCompletedRun` 时页面主体是 §D6 空态：`还没有运行过 QA` / `运行一次检查以获得问题清单` / `[运行 QA]`。

## 2. 导出复核（Surface `export`）

### 2.1 定位

这是**交付门禁**页（PRD H-09）。它要清楚回答三件事：
**能不能导出 / 为什么不能 / 导出后会发生什么。**

### 2.2 版面

```

│  导出复核                                                                   │
│  Master Services Agreement.docx · 1,248 段                                  │
├────────────────────────────────────────────────────────────────────────────┤
│  ▎ 导出被阻断                                                               │
│  2 个未处理的 QA 错误会阻止导出。修复后重新检查，或记录理由后覆盖门禁。         │
│  [查看问题 →]  [重新检查]                                                    │
├────────────────────────────────────────────────────────────────────────────┤

│  △ 警告            1      不阻断，建议处理                                    │
│  ✓ 已检查段落   1,248 / 1,248                                               │

└────────────────────────────────────────────────────────────────────────────┘
```

### 2.3 要点

| 项 | 规格 |
| --- | --- |
| 顶部横幅 | §A8，阻断时 `--err` 左缘（允许低透明斜纹）；通过时 `--ok` 左缘 + `可以导出` |
| 门禁项 | 每项：图标 + 名称 + Mono 数值 + 一句判定。**四项全部显示**（包括通过的），让用户知道检查了什么 |
| **降级清单** | PRD B 专述硬要求："不可保真元素导出时附清单"。**这是本页最被低估的一块**，必须列出具体项与位置，可点击定位 |
| 覆盖门禁 | §G8 Waiver：必填理由 + 操作人 → 二次确认对话框说明"此次覆盖会被记录" → 导出。按钮是 `danger` 变体 |
| 导出中 | 页面切换为进度态：4px 确定性进度条 + 当前阶段文字（`正在重建文档结构…`）+ `在后台继续`。**离开页面不取消导出** |
| 完成 | `--ok` 横幅 + 输出路径（可点击打开所在文件夹）+ `再导出一份` + 本次降级清单副本 |
| 失败 | §F5 Error State：失败原因、已完成到哪一步、原文件未被修改的保证、`重试` / `查看诊断` |

## 3. 审校模式（工作台内的渲染模式，不是独立页）

### 3.1 为什么不做成独立页

审校者需要的是"带修订痕迹的同一张网格"，不是另一个界面。
独立页会导致筛选、预览、术语、TM 全部要重做一遍。

### 3.2 进入与呈现

- 入口：命令面板 `审校模式`，或洞察 → 讨论/队列的 `开始审校`。
- 进入后网格顶部插入 **36px 模式条**（`--ink` 面）：
  `审校模式 · 修订痕迹显示中 · 已处理 12 / 48` + `退出审校`。
- 译文单元格渲染为 §D8 词级 diff（删除线 + 下划线），原值可 hover 查看。
- 每行右侧出现 `接受` / `拒绝` 两个 `ghost` 按钮（`Ctrl+↑` 接受 / `Ctrl+↓` 拒绝）。
- 状态流：`翻译 → 审校 → 签发`（`workbench.workflowState`）。可裁剪（个人可关审校）。

### 3.3 双语 DOCX 往返（PRD I-03）

见 `screens/assets.md §5`（互操作）。回导后的修订以本模式呈现，
并在行内标注来源：§G5 Provenance Strip `来自双语审校回导 · <文件名> · <时间>`。

### 3.4 签发

- `签发` 需要满足审校策略（`setup.requireReview` / `allowDirectSignOff`）。
- 已签发段落变为只读（`workbench.signedReadOnly`），状态方灯加外框，
  尝试编辑时给出内联提示 + `撤销签发` 动作（需权限与理由）。
- 绕过审校直接签发（`workbench.reviewBypass`）必须走 §G8 Waiver。
