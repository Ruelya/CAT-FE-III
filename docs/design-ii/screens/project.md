## 1. 项目首页（无活动项目时的 Surface）

### 1.1 推翻了什么

实拍 `02-home-empty-active.png`：左侧 230px 常驻导航（Projects/Search/Templates/Recycle）+
右侧标题 + 一个虚线大空框 + 居中按钮。是一个标准后台模板。
问题：230px 侧栏承载 4 个项，浪费；空态是一个巨大虚线矩形，无信息；
非对称构图缺失；标题下方 `0 projects in this view` 是废话。

### 1.3 项目卡（Project Card）

不是圆角卡片，是**板块 + 缝**构成的网格单元：

```
┌────────────────────────────────┐
│▎ Craft Contracts 2026          │  ← 左缘 3px Band Echo（本页唯一 Echo）
│  法律 · EN-US → ZH-CN          │     标题 Jost 20/500
│                                │     副行 --t-meta
│  ▓▓▓▓▓▓▓▓▓▓▒▒▒▒░░░░░  62%      │  ← 4px 堆叠比例条（真实状态占比）
│                                │
│  8 文件   1,248 段   ● 3 问题   │  ← Mono 计数；问题>0 时方灯为 --err
│  2026-08-01 更新                │
│                            ⋯   │  ← hover 才出现的溢出菜单
└────────────────────────────────┘
```

- 网格：`repeat(auto-fill, minmax(280px, 1fr))`，gap **0**，卡之间用 `--rule` 缝分隔（板块制）。
- hover：`--shade` 底；聚焦：左缘 Active Axis。
- 点击打开项目：触发 `project-open` 转场——**卡片用 View Transition FLIP 放大成工作台的标识板**
  （共享 `view-transition-name: project-identity`）。这是全应用最强的一次转场，仅此一处。
- 溢出菜单：打开 / 重命名 / 另存为模板 / 归档 / 移入回收站（danger）/ 导出归档包。

```css
.project-card { view-transition-name: none }
.project-card[data-opening] { view-transition-name: project-identity }
```

### 1.4 四个 Tab

| Tab | 内容 | 要点 |
| --- | --- | --- |
| **项目 n** | 卡片网格 + `Active / Archived` §C8 分段控件 + 分页 | 归档项目卡降饱和（`filter: saturate(.6)`）+ 角标 `已归档` |
| **搜索** | 跨项目搜原文/译文/备注（`home.globalSearch*`） | 搜索框 + 字段选择（全部/原文/译文/备注/文档/项目）+ 工作流状态筛选。结果按项目分组，每条显示段号、上下文片段、命中高亮（`--signal-ink` 加粗）、点击直达。**与命令面板 `#` 前缀共用后端** |
| **模板 n** | 项目模板列表（`home.projectTemplates`） | 每行：名称、描述、内置/自定义标记、语向、依赖的 QA/AI/分析/管线配置、修订号。动作：编辑、复制、删除。新建模板对话框用 §A5 |
| **回收站** | 可恢复删除（`home.recycle*`） | 每行：类型（项目/文档）、名称、删除时间、保留至。动作：恢复、永久清除（**需输入名称确认**）。顶部说明保留策略 |

### 1.5 其他

- **恢复归档包**：Masthead 右侧次级按钮 `恢复归档`，打开文件选择 → 预览包内容（项目名、文件数、段数、资产切片）→ 确认恢复。
- **刷新**：左栏底部，`--t-meta` 文字按钮 + 最后刷新时间。**不用浮动 FAB**。
- **设置入口**：Index Spine 工具区（删除实拍里右下角的浮动齿轮 `shell-settings-fab`）。

| 缺陷 | 修复 |

### 2.3 三步内容

| 步 | 标题 | 内容 | 前进条件 |
| --- | --- | --- | --- |
| **01** | 项目 | 项目名（必填）· 源语言 · 目标语言 · 领域（可选）· 工作区位置（只读路径 + 更改） | 名称非空 且 源≠目标（`setup.languagesMustDiffer`） |
| **02** | 配置 | 见上图三组 | 无（都有默认值） |
| **03** | 文件 | §C10 拖放区 + `选择文件` / `选择文件夹` · 已选列表（名称/类型/大小/可移除）· 导入模式（`全部成功才建项目` / `尽力导入`，`setup.allOrNothing` / `setup.bestEffort`） | 至少 1 个源（或允许空项目后续添加） |

**第 3 步的导入进行中**：把右栏换成**导入进度**：每文件一行 + 4px 进度条 + 状态；
底部一个 Live Matrix 显示已抽取段落的累计（每点 = 一个文档）。
**失败必须给可理解错误**（PRD B 验收：禁止静默丢内容），失败行可展开看诊断详情、可重试、可跳过。

### 2.4 转场

步进用 `wizard-next` / `wizard-back` 类型：**左栏构图完全不动**（`view-transition-name: none`），
只有右栏内容区做 ±16px 方向位移 + 淡入（`--d-page` 280ms）。步进器的 Active Axis 做 160ms 迁移。

### 2.5 禁止

- ❌ 倒计时式步骤名（`T-3` / `LAUNCH`）
- ❌ 居中大 hero 布局
- ❌ 三张等宽营销卡
- ❌ 把"高级选项"全部塞进第 2 步——超出 8 个字段就折叠为 `更多选项 ▾`

- 每个数据块底部**必须有一个动作**（`按匹配档筛选段落` / `前往 QA 复核` / `前往 AI 控制台`），
  否则该块违反"没有用户决策关联的仪表盘内容"禁令。
- 分析过期（`insights.analysisStale`）时，进度块顶部插入 §A8 Banner：
  `分析结果早于最近一次导入，数字可能不准` + `重新运行分析`。

### 3.3 文件（Files）

§D1 数据表：文件名 / 类型 / 段数 / 4px 进度条 / 问题数 / 修订号 / 最后更新 / 动作。
行展开显示：结构路径、源哈希、字数（词/字符/CJK 字符）、加权字数（按匹配档折算）。
顶部：拖放区（加文件/加文件夹）+ 批量动作（预翻译、运行 QA、移入回收站）。

### 3.4 分析（Analysis）

字数分析与加权字数（PRD K-01/K-02）。
- 匹配档分布表：`101% / 100% / 95–99 / 85–94 / 75–84 / 50–74 / 无匹配 / 内部重复`
  → 每档：段数、词数、CJK 字符数、折算系数、等效工作量。
- **明确标注"用于估算投入，不用于计价"**（PRD 范围门禁）。
- 快照对比：本次 vs 上次分析的差值（`+` 绿 / `−` 赭）。
- 一个 §D3 堆叠比例条呈现匹配档构成。

### 3.5 重导入（Reimport）

- 选择新版源文件 → 预览协调结果：
  Live Matrix（每点 = 一段，状态 = `未变 / 已变 / 新增 / 删除`）+ 计数表。
- 差异列表：旧序号 → 新序号、原文 before/after 的 §D8 词级 diff、保留的译文、被标为待译的段。
- `应用重导入` 需二次确认，并说明"保留 n 段译文，m 段标记为待译"。**可回滚**（快照）。

### 3.6 讨论（Discussions）

段级讨论线程（`discussion.*`）。
左 320px 线程列表（标题/范围/消息数/状态/最后更新，可筛选 `包含已解决`），
右侧消息流（作者、时间、正文、编辑/删除、@提醒）。
- 已删除消息显示**墓碑**（`discussion.tombstone*`）：`--frame` 底 + 说明"此消息已删除"，不隐藏痕迹。
- 已解决线程整体降饱和 + `已解决` 标记 + `重新打开` 动作。
- 新建线程可绑定段落范围（有上限 `discussion.segmentLimit`，超限时明确提示）。

### 3.7 任务包（Task Package）

离线交接（PRD I-04）。两个模式（§C8）：**导出任务包** / **导入回传**。

- **导出**：选择文件/段落区间 → 选择资产切片（TM/术语，可加多条 slice）→ 填说明 →
  预览包内容（文档数、段数、资产行数、依赖）→ 导出 `.tltask`。
  包**不可变**（`task.exportImmutable`），导出后显示哈希与创建时间。
- **导入回传**：选择包 → **预览合并**：每行显示 `本地已变 / 远端已变 / 双方都变 / 相同编辑`
  四种分类（`task.localChanged` 等），冲突行必须人工选择。
- 合并是**事务性**的（`task.transactionalMerge`）：要么全应用要么全不应用，并说明这一点。
- 缺失依赖（`task.missingDependency`）阻断应用并列出缺什么。

### 3.8 插件（Plugins）

见 `screens/ai.md §4`。

### 3.9 归档与快照（Archive & Snapshots）

- **归档**：导出 `.tlcat` 单文件归档包（跨机完整恢复，PRD A-06）。显示包含内容清单与体积估算。
- **快照**：项目检查点列表（`snapshot.*`）。每条：名称、创建者、创建时间、基线修订、
  变更摘要（文档 +2 / 段落 ~148 / 挂载 +1 / 讨论 ~3）。
- 恢复流程：`预览恢复` → 显示将发生的变更（新增/修改/删除计数）→ 缺依赖时阻断 →
  `原子恢复` 二次确认（`snapshot.atomicRestore`）。
- 检查点**不可变**（`snapshot.immutableCheckpoint`），文案要说明这点。

### 3.10 对齐与语料 / 资产养护 / 互操作
