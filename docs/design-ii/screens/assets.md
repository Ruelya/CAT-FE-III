### 1.2 左栏：库列表

每条：库名、Mono 句对数、读写标记（`写入` / `只读参考`）、语向、挂载来源（项目/全局）。
当前项左缘 Active Axis。底部 `挂载库…`（打开挂载对话框：选择已有库 / 新建 / 导入 TMX）。

**读写区分必须显眼**（PRD D-01）：只读库名后跟 `--t-micro` 的 `只读参考` 标记，
且其条目在匹配面板中的来源标签也带此标记。

### 1.3 右栏：健康度 + 检索 + 维护台

- **健康度 Live Matrix**：每点 = 一个采样桶，状态 = `干净 / 疑似重复 / 语义存疑 / 已隔离`。
  点击某点 → 进入养护页并预筛选该桶。**这是资产中枢"活性"的第一眼呈现。**
- **检索**：查询框 + 字段（原文/译文/双向）+ 模式（精确/模糊/Concordance）+
  元数据筛选（领域、项目、作者、时间范围，PRD D-05）。
  结果行：匹配率 + 原文 + 译文 + `库 · 日期 · 来源文档 · 段号`。
  行内动作：编辑、删除、复制、`在编辑器中查看来源`。
- **维护台**（PRD D-06）：进入一个受控的批量视图：
  去重（精确/近似，可设阈值）、批量替换（**必须先预览再执行，可撤销**）、合并库、按元数据批删。
  所有批量操作走 §G8 Waiver 式的确认（说明影响条数 + 可回滚）。

### 1.4 惩罚与匹配设置（PRD D-04）

抽屉：来源惩罚、格式差异惩罚、大小写差异惩罚、CJK 分词权重、
`101% 上下文匹配` 开关。每项带一句"这会让匹配率如何变化"的说明与一个示例。

## 2. 术语库

### 2.1 版面

左栏库列表（同 §1.2），右栏词条表（§D1）：
`原文 / 目标语 1 / 目标语 2… / 词性 / 状态 / 领域 / 更新时间`。

- **状态**：`首选` / `允许` / `禁用（禁译）` / `待定`。
  `禁用` 用 `--err-ink` + 叉形标记——它会直接触发 QA 报错（PRD E-05）。
- 行展开：定义、例句、备注、来源、附图（P2）。
- 顶部：搜索 + 状态筛选 + 领域筛选 + `新建词条` + `导入`（TBX/CSV/Excel）+ `导出`。
- **AI 术语提取**（PRD E-06）入口在此：`从文档提取候选 →` 进入养护页的术语挖掘。

### 2.2 快速添加（工作台内）

`Ctrl+Q` 从选区添加：小型 §A5 Dialog，预填原文（选区）与译文（译文单元格选区），
只要求：目标库、状态。其余字段可后补。**≤3 个必填字段，否则译员不会用。**

## 3. 养护（AC 模块 · 产品差异化的核心）

### 3.1 定位

PRD：`中枢的价值不在"存了多少"，而在"存的东西有多干净、多可用"`。
本页是"资产沉淀中枢"从口号变功能的地方，因此它是**资产 Surface 的默认落地页**。

### 3.3 硬规则（PRD AC-08 / AC 验收）

| 规则 | 界面兑现 |
| --- | --- |
| **可解释** | 每条发现必须显示：发现类型、判据数值（相似度/语义分/长度比）、相关单元、判定引擎（若语义层） |
| **可预览** | `应用` 前必须走 `预览变更`：列出将被隔离/修改的条目样本 + 总数 + 影响的库修订 |
| **可回滚** | `导出回滚包` 在应用前生成；应用后在运行历史里保留 `回滚此次运行` 动作 |
| **原始保留** | 隔离 ≠ 删除。隔离区是一个可浏览、可恢复的分区，界面必须能进入它 |
| **零高质量误删** | 应用对话框必须显示 `其中 n 条质量分 ≥ 80，确定隔离？`，高分条目默认**不勾选** |
| **修订安全** | 若库修订已变（`curation.staleRevisions`），阻断应用并要求重新分析 |
| **只读库** | 只读库只能分析不能应用，按钮禁用并说明原因（`curation.readOnly`） |

### 3.4 术语挖掘与漂移报告

- **术语候选**（AC-06）：表格 `候选原文 / 建议译法 / 出现次数 / 一致率 / 来源分布 / [确认加入术语库] [忽略]`。
  批量确认前必须预览。
- **漂移报告**（AC-07）：分组呈现 `同一原文 → 多种译法`：
  组头是原文 + 译法数；组内每条译法：文本、出现次数、占比条、最近使用时间、来源项目。
  动作：`选为标准并批量归一`（**必须预览受影响段落数**）。

### 3.5 离线 vs 引擎模式

- **离线检查**（`curation.modeOffline`）：纯规则层，无网络，无成本。默认。
- **引擎精修**（`curation.modeProvider`）：语义层，需 AI 配置档。
  必须显示：使用哪个引擎/模型、预估调用量与 token 成本、可随时中止。
  **无配置档时按钮禁用**并给出 `前往 AI 控制台配置 →`。

## 4. 对齐与语料

### 4.1 两个模式（§C8）：**文档对齐** / **参考语料**

### 4.2 文档对齐器（PRD J-02 / J-04）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 会话  MSA 中英对齐            源 msa-en.docx (412 段) 目标 msa-zh.docx (398)│
│ [AI 智能对齐]  配置档 [默认 ▾]                              [应用到 TM]    │
├────────────────────────────┬─────────────────────────────────────────────┤
│ 源                          │ 目标                                         │
│ 1  This Agreement is…      ══ 1  本协议自…                    高  ✓       │
│ 2  The Parties agree…      ══ 2  双方同意…                    高  ✓       │
│ 3  All notices shall be…   ╲                                             │
│ 4  and delivered as…       ══ 3  所有通知…并按第 12 条…       中  ⚠       │
│ 5  The confidentiality…     ══ 4  保密义务…                    低  ⚠       │
│ 6  （未对齐）               ──                                            │
└────────────────────────────┴─────────────────────────────────────────────┘
```

| 项 | 规格 |
| --- | --- |
| 连线 | 源/目标之间的连接线：1:1 用 `══`；n:1 / 1:n 用汇聚折线；未对齐用 `──` 到空槽 |
| 置信度 | 每条 `高 / 中 / 低`（`--ok` / `--warn` / `--err` 方灯）。低置信度默认不入库 |
| 手工修正 | `链接`（选中一源一目标）· `断开` · `合并`（多段合一）· `拆分`。全部有快捷键，可撤销 |
| Live Matrix | 页头一条：每点 = 一个候选对，状态 = 置信度档。给"哪一段开始错行"一个直观答案 |
| 应用 | `应用到 TM` 需选择可写库；显示将写入条数；低置信度条目需显式勾选 |
| 终态锁 | 会话应用后进入终态（`alignment.terminalLocked`），只读并显示结果摘要 |

### 4.3 参考语料（LiveDocs 式，PRD J-03）

- 语料列表：名称、种类（双语 / 单语源 / 单语目标）、条目数、挂载状态、修订、来源。
- 导入：拖入文件 → 选择种类 + 语向 → 建立索引（进度用 Live Matrix，每点 = 一个文档）。
- 检索：查询 + 侧（源/目标/双向）→ 结果含**结构路径与出处**（`corpus.structuralPath`、
  `corpus.noProvenance` 时明确说"该条目无出处信息"，不伪造）。
- 挂载后立即参与编辑器的匹配检索与 LLM 接地——界面上要**明说这一点**。

## 5. 互操作

### 5.1 两个模式（§C8）：**双语表 → TM** / **双语审校 DOCX 往返**

### 5.2 双语表 → TM（PRD J-01）

选择 docx/xlsx 对照表 → 选择表格与列映射（源列 / 目标列 / 备注列）→
**预览前 20 行**（`interop.tablePreviewReady`）→ 选择可写库 + 填写导入理由 → 应用。
- 缺源/缺目标的行标红并计数（`interop.missingSource` / `missingTarget`），可选择跳过或阻断。
- 无可写库时阻断并给出挂载入口（`interop.noWritableLibrary`）。

### 5.3 双语审校 DOCX 往返（PRD I-03）

**导出**：选择文件与段落范围 → 生成三栏 Word（原文 / 译文 / 审校意见）→ 说明"给领域专家改"。
**回导**：选择改后的 docx → **预览合并**：
每行 `段号 / 当前译文 / 回传译文 / 分类`，分类为
`未变 / 已修改 / 空回传 / 冲突（本地也改了）`（`interop.unchangedTarget` 等）。
- §D8 词级 diff 呈现 before/after。
- 已签发段落（`interop.signedReview`）默认不覆盖，需显式解锁。
- 应用需填理由（`interop.reviewImportReason`），结果进入审校模式呈现（`quality.md §3.3`）。

## 6. 空态与错误

| 情况 | 呈现 |
| --- | --- |
| 未挂载任何 TM | §D6：`还没有挂载翻译记忆库` / `挂载一个库后，你确认的每一段都会自动沉淀进来` / `[挂载库] [导入 TMX]` |
| 检索无结果 | `没有匹配 "xxx"` + 显示当前生效的筛选条件 + `清除筛选` |
| 未运行过养护 | `还没有分析过这个库` / `分析会检查重复、错位、错语言与质量分，不会直接修改数据` / `[分析]` |
| 引擎精修不可用 | 模式选项禁用 + 一行说明 + `前往 AI 控制台配置 →` |
| 库修订已变 | §A8 `--warn` 横幅：`这个库在分析后发生了变化，结果可能已过期` + `重新分析` |
| 分析中 | 确定性进度条 + 已分析计数 + `在后台继续`（离开页面不中断） |
