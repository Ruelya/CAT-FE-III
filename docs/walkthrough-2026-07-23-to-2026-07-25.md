## 23 July — closing the product gaps

The work shifted from early MVP slices toward the full PRD gap matrix. The
important change in mindset was to treat the desktop application as a real
product boundary around the Rust Engine:

- durable state and policy stay in the Engine;
- Electron owns OS dialogs, process lifecycle, recovery, and packaging;
- React owns presentation and ephemeral interaction state;
- tests use the real Engine wherever persistence or protocol behavior matters.

The product-shell and release-packaging task was reopened because the earlier
MVP implementation did not satisfy the PRD's non-MVP requirements. This added
localization, recovery, accessibility, backup/restore, update, tutorial, and
packaging evidence to the active scope.

## Lessons from the three days

1. **MVP is not the same as product completion.** A screen or configuration
   stub does not satisfy a PRD item that requires lifecycle, failure recovery,
   accessibility, or release evidence.
2. **Locale is part of the test contract.** A test must establish its locale
   before the first UI action; changing it after setup has already rendered is
   too late for exact accessible-name locators.
3. **Seams must be outside live data.** A backup destination or fixture path
   inside the active data directory can make a test pass while violating the
   real no-clobber/rollback contract.
4. **Generated/catalog copy is an API.** E2E assertions should use the actual
   accessible name from the catalog, not a remembered English label.
5. **Cross-layer work needs a real boundary.** Renderer convenience must not
   replace Engine policy, archive parsing, revision handling, or process
   recovery.
6. **Evidence takes time.** Real Electron + Rust E2E runs are much slower than
   unit tests, and platform packaging cannot be inferred from a local static
   build.
